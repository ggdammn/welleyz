# welleyz — Git и гейты качества

Эти правила применяются к каждой задаче агента, включая задачи только с документацией. Каждая **завершённая** задача заканчивается отдельным локальным коммитом после полного прохода гейтов; не объединяйте несвязанные задачи в один коммит. Push выполняется только по явному запросу. Если обязательный гейт не прошёл, задача остаётся незавершённой: исправьте причину и повторите гейты до коммита; если исправление выходит за пределы задачи, сообщите о блокере пользователю.

## До работы и до staging

1. Зафиксируйте исходное состояние через `git status --short --branch`; изучите затронутые файлы. Существующие правки, удалённые/перенесённые файлы и неотслеживаемые файлы могут принадлежать пользователю. Не перезаписывайте их и не включайте в свой коммит без явной необходимости и согласования.
2. Разделите изменения на относящиеся к задаче и чужие. Проверьте `git diff`, `git diff --cached`, список неотслеживаемых файлов и `git log --oneline -10`. Не используйте `git add .`, `git add -A`, `git commit -a`; индексируйте только точные пути задачи. Если файл уже изменён пользователем, индексируйте только свой hunk или согласуйте совместный коммит.
3. Не коммитьте ключи, настройки машины, пользовательские пресеты, PNG-проверки, логи, временные файлы, кэш и артефакты сборки. Папка `local/` остаётся локальной. Если корневой `.gitignore` исключает новый файл правил в `docs/` или `AGENTS.md`, добавьте его явно командой `git add -f -- <точный путь>`; существующие отслеживаемые документы индексируйте обычным `git add -- <точный путь>`.

## Полные гейты перед каждым коммитом (Windows)

Выполняйте из корня репозитория, на окончательной версии файлов задачи. Успех ранее собранной конфигурации не заменяет новый build и новый запуск тестов. Останавливайтесь на первом сбое, исправляйте и запускайте гейты заново.

```powershell
cmake --preset windows-release
cmake --build --preset windows-release
& 'build/ProcessorBehaviourTest_artefacts/Release/ProcessorBehaviourTest.exe'
& 'build/EditorSmokeTest_artefacts/Release/EditorSmokeTest.exe'
& 'build/FxEngineTest_artefacts/Release/FxEngineTest.exe'
& 'build/PresetCompatibility_artefacts/Release/PresetCompatibility.exe'
& 'build/StandaloneTransportTest_artefacts/Release/StandaloneTransportTest.exe'
```

`CMakePresets.json` собирает VST3, Standalone и пять тестовых целей. В `CMakeLists.txt` тесты не зарегистрированы через `add_test`, поэтому `ctest` не является заменой прямому запуску всех пяти исполняемых файлов. Проверьте ненулевой exit code каждой команды; пустой вывод не означает успех. Если меняется упаковка/релиз — дополнительно выполните затронутый release/installer сценарий (`python scripts/release.py`, требует Inno Setup 6) и проверьте итоговый пакет. Для затронутых C++ файлов дополнительно проверьте форматирование по `.clang-format` (`clang-format --dry-run --Werror <файл>`); не переформатируйте чужие файлы целиком ради этой задачи. Для изменений UI добавьте визуальную проверку, указанную в [UI_STANDARDS.md](UI_STANDARDS.md).

## Коммит

1. После успешных гейтов выполните `git diff --check`, просмотрите `git status`, `git diff` и `git diff --cached` (после точечного staging). Убедитесь, что staged diff содержит только завершённую задачу и в нём нет секретов и артефактов. Если после проверки изменился исходный код, настройки сборки или проверяемое поведение, повторите соответствующие полные гейты перед коммитом.
2. Создайте один понятный коммит задачи в стиле `docs: add agent and UI standards`, `feat: add ...`, `fix: ...`, `test: ...`, `refactor: ...` или `chore: ...`. Не отключайте hooks и не делайте пустой коммит.
3. Сверьте `git status --short --branch` и сообщите хеш коммита, результаты гейтов и какие ранее существовавшие незакоммиченные изменения остались в дереве. Коммит не означает push.
