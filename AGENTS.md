# welleyz — руководство для агентов

Работайте с текущим состоянием дерева: это C++20/JUCE 8.0.8 синтезатор с VST3 и Standalone. Основной код — `src/`, поведенческие проверки — `tests/`, сборка — `CMakeLists.txt` и `CMakePresets.json`. Сохраняйте чужие незакоммиченные изменения.

## Обязательные документы

- [Стандарт UI](docs/UI_STANDARDS.md) — визуальная идентичность существующего редактора, компоненты, состояния и визуальная проверка. Читать перед изменениями интерфейса.
- [Стандарт Git и проверок](docs/GIT_STANDARDS.md) — обязательные гейты и отдельный коммит для каждой завершённой задачи. Читать перед началом работы и перед коммитом.

Прямое требование пользователя имеет приоритет. Если правило конфликтует с задачей или выполнить гейт невозможно, сообщите причину и согласуйте дальнейшие действия; не объявляйте проверку успешной и не создавайте коммит с непроверенной задачей.

## Рабочий цикл

1. Перед правкой посмотрите `git status` и код, затрагиваемый задачей. Не включайте в коммит существующие изменения пользователя, временные файлы, сборочные артефакты или секреты.
2. Для UI опирайтесь на работающий редактор и `docs/UI_STANDARDS.md`; базовые токены — `src/DesignTokens.h`, пользовательский акцент — `src/ThemeManager.h`, общая отрисовка — `src/Theme.h`. Поведение синтеза и состояние параметров остаются в процессоре; UI использует JUCE/APVTS.
3. Делайте минимально необходимое изменение в принятом стиле. На audio thread нет выделений памяти, блокировок и ввода-вывода; `paint()` и `resized()` не ждут IO.
4. Перед каждым коммитом выполните полный набор проверок из `docs/GIT_STANDARDS.md`, просмотрите точный состав staged diff и создайте один осмысленный коммит для задачи. Не отправляйте изменения в remote без отдельного запроса.

Примечание: текущий `.gitignore` исключает `docs/` и корневой `AGENTS.md`. Новые файлы правил при первом добавлении нужно явно индексировать через `git add -f -- <путь>`; уже отслеживаемые файлы обновляются обычным `git add -- <путь>`.
