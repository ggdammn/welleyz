# welleyz — стандарт интерфейса

Эталон — текущий редактор `WelleyzEditor` в `src/PluginEditor.cpp` / `.h`, его `WelleyzLookAndFeel` и ассеты из `src/assets/`. Новая панель, элемент или состояние должны выглядеть частью этого же инструмента на Windows, в Standalone и в окне VST3. Изменение всей визуальной системы требует отдельной задачи, а не происходит побочно при добавлении компонента.

## Композиция

- Редактор проектируется в координатах 1280 × 760 (`kEditorDesignWidth/Height`), затем масштабируется единым коэффициентом от 50 до 200 %. Новые размеры и толщины масштабируются тем же коэффициентом один раз; при масштабировании не теряются подписи, фокус и кликабельные области.
- Шапка содержит фирменный знак и вкладки `RANDOM` / `OSC` / `FX`, справа — компактные служебные кнопки. Нижняя полоса общая для страниц: PITCH, MOD, клавиатура, VOLUME. Не переносите эти зоны без отдельного требования.
- `RANDOM`: слева SOUND TYPE, в центре крупное круглое действие RANDOMIZE и ряд BACK / RESET / SAVE / LOAD, справа поиск и список PRESETS. `OSC`: три равноправные полосы осцилляторов над ENVELOPE / FILTER / TUBE + LO-FI / MASTER + ARP. `FX`: сетка 2 × 2 из FILTER / HAZE / TAPS / SPACE. Новое управление размещается внутри своей функциональной группы, с отступом от соседних элементов; родитель управляет расположением детей.

## Цвет, материал, форма

- Основа — тёмный холодный студийный корпус: `kBackground #0c0f14`, `kSecondary #15191f`, `kSurface #222830`; наведение `kHover #303840`, активная подложка `kActive #3b454e`. Светлый основной текст `kText #f4f6f5`, вторичный `kSecondaryText #d2d9da`, приглушённый `kMuted #a3afb3`. Источник значений — `src/DesignTokens.h`, не копируйте hex в компоненты.
- Акцент по умолчанию бирюзовый `kDefaultAccent #22dccb`, но пользователь может его менять. Для состояний используйте `ThemeManager::primary()/hover()/pressed()` и `makeWaveTheme()`, а не фиксированный цвет. `kModulation`, `kViolet`, `kOnLed`, `kOffLed` имеют отдельные смысловые роли: модуляция, фоновый оттенок, включение/выключение. Проверяйте читаемость текста на светлом и тёмном пользовательском акценте.
- Сохраняйте послойную отрисовку нынешнего редактора: холодные градиенты корпуса, мягкие тени, тонкая окантовка и световая кромка панелей, слабый шум, локальное акцентное свечение активных элементов. Общие эффекты — `fillPanel`, `drawHalo`, `drawAccentGlow` в `src/Theme.h`; новые панели должны пользоваться ими или следовать их визуальной логике. Не заменяйте корпус плоскими карточками и не усиливайте свечение так, чтобы оно перекрывало значения и подписи.
- Радиусы и отступы берите из `welleyz::design::radius` (8 / 11 / 14 / 18 px, полный круг при необходимости) и `welleyz::design::spacing` (4 / 8 / 12 / 16 / 24 px). Не вводите другую шкалу для соседних контролов. Круглая центральная кнопка RANDOMIZE — главный визуальный акцент, остальные действия сохраняют более спокойную иерархию.

## Типографика, иконки и элементы

- Заголовки и акцентные подписи — встроенный Syne (`welleyz::fonts::display`), основной текст и значения — встроенный Outfit (`welleyz::fonts::mono` в существующем API), логотип — Sarina (`brand`). Имена ресурсов и загрузка определены в `src/StudioFonts.h`. Не заменяйте их системным или новым шрифтом в отдельных панелях.
- Сохраняйте текущую иерархию: короткие прописные обозначения разделов/параметров, различимые числовые значения, компактные вторичные пояснения. При новом тексте проверяйте ширину на 50 % и длинные названия пресетов: текст не должен обрезать соседний контрол. У значения всегда видна единица измерения там, где она есть у аналогичных параметров.
- Переиспользуйте стили `WelleyzLookAndFeel` для JUCE Button, Slider, ComboBox, TextEditor и MIDI-клавиатуры. Новая ручка, переключатель, выпадающий список или кнопка по форме, состояниям и толщине линий согласуются с ближайшим существующим аналогом. Если элемент встречается повторно, вынесите общий вид/поведение вместо локальных расхождений.
- Иконки берите из `src/assets/icons/`, масштабируйте без искажения; новые SVG согласуйте с текущим весом штриха и используйте цвета темы. У кнопок без текстовой подписи должны быть имя и tooltip.

## Состояния и взаимодействие

- Различайте normal / hover / pressed / selected / disabled / focus не только цветом: используйте положение, контур, подпись, значок или заполнение, как в существующих контролах. Видимый фокус не должен исчезать на светлом или тёмном акценте. Поддерживайте доступ с клавиатуры: Tab до действий, Enter/Space для активации, стрелки в списках, Escape для закрытия оверлеев.
- Редактирование текста и сочетания клавиш DAW имеют приоритет перед игрой на компьютерной клавиатуре. Параметры звука подключайте через APVTS attachments; пользовательский цвет/масштаб — настройки интерфейса, не данные звукового пресета.
- Анимации — только короткая обратная связь (например, текущая реакция RANDOMIZE, LED и клавиш), статический признак состояния обязателен. При доступном системном reduced motion эффекты должны отключаться без потери информации. Избегайте файловых/сетевых операций в `paint()` и `resized()` и блокировок audio thread.

## Проверка изменений UI

После полных гейтов из [GIT_STANDARDS.md](GIT_STANDARDS.md) запустите `EditorSmokeTest` с локальным путём к PNG, чтобы получить `-random.png`, `-osc.png`, `-fx.png`; сравните каждую страницу с текущим видом. Проверьте затронутые состояния: выбранный/выключенный/недоступный элемент, поиск без результатов, оверлей, контраст при изменённом акценте, читаемость и расположение при 50 / 75 / 100 / 150 / 200 % (если соответствующая страница затронута). Скриншоты храните вне Git, например в `local/`. Отмечайте в отчёте, какие экраны и состояния действительно просмотрены; тест на пиксельное совпадение не заменяет осмотр.
